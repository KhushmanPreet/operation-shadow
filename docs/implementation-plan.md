| **M2: Backend Contracts and Persistence** | 1. Implement all 6 ER diagram SQLAlchemy 2.0 models in `db/models.py` (`Mission`, `Task`, `Vehicle`, `Observation`, `Event`, `ReasoningTrace`) with relationships, indexes, `CheckConstraint`s, and `PRAGMA foreign_keys=ON`.<br>2. | **M3A: Vehicle Abstraction and Simulation** | 1. Define `VehicleAdapterPort`, `ClockPort` (`SystemClock`, `ManualClock`), and `LockedRealVehicleAdapter` in `ultron_stub/vehicle_adapter.py`.<br>2. Deterministic mock `SCOUT01` and `HAWK01` execute movement, battery updates, observations, and command acks using `ManualClock` without real-time sleeps.<br>3. Missed heartbeats transition vehicles to `UNKNOWN`; stale telemetry is rejected; fresh heartbeats recover state to `UNKNOWN` -> `CONNECTED`.<br>4. Background tasks clean up with zero leaked tasks on `stop()`. | **Backend (`test_milestone3a_vehicle_simulation.py` & `mypy`)**: Verify adapter behavior, dual mock vehicles, heartbeat timeout/recovery, stale rejection, DB persistence boundary, and background task cleanup. |
| **M3B: Backend REST API and Dashboard WebSocket Gateway** | 1. Implement REST endpoints in `api/mission.py` (`POST /mission`, `GET /mission/{id}`, `GET /mission/{id}/replay`), `api/vehicle.py` (`GET /vehicle/{id}/status`, `/sensors`, `/observations`, `POST /command`, `POST /simulate`), `api/events.py` (`GET /events`), and `api/map.py` (`GET /map`).<br>2. Implement `websocket/dashboard_gateway.py` (`/ws/dashboard`) with full-state snapshot on connect, snapshot-to-live synchronization buffering, multi-client broadcast, and bounded slow-client eviction. | 1. Connecting to `/ws/dashboard` immediately delivers a full `DashboardSnapshotEnvelope` followed by live `telemetry`, `event`, `reasoning_trace`, and `mission_status` pushes without losing concurrent updates during snapshot construction.<br>3. Slow or failed WebSocket clients are evicted without blocking healthy clients. | **Backend (`test_milestone3b_api_and_dashboard_ws.py` & `mypy`)**: Verify all REST endpoints, auth, replay ordering, WebSocket snapshot-to-live sync, multi-client broadcast, and slow-client eviction. |
